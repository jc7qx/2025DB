# 第一節 資料定義語言(Data Definition Language, DDL)

SQL指令用於定義資料庫綱要(schema)，建立及修改資料的結構。
## 1.1創建資料庫
在資料庫管理系統中，可以經由`CREATE DATABASE`之SQL指令建立新資料庫。
```sql
CREATE DATABASE new_db_name
```
為預防新建資料庫名稱與已有的資料庫明成相同造成執行錯誤，可以利用 `IF NOT EXISTS`來限制資料庫的新增。
```sql
CREATE DATABASE IF NOT EXISTS new_db_name
```

在SQLite3資料庫管理系統沒有 CREATE DATABASE 指令用於建立新資料庫，可以在命令列模式輸入 >sqlite3 neDB 建立一個新資料庫。

## 1.2創建資料表
關聯式資料庫由資料表所組成，因此在一個資料庫中創建資料表必須賦予資料表名稱、屬性、定義完整性限制條件。其中屬性資料包括名稱、資歷型別、及限制。以會員(member)資料表為例。
```sql
CREATE TABLE Member (
	mId CHAR(8) NOT NULL,
	pId CHAR(10) NOT NULL,
	name VARCHAR(8) NOT NULL,
	birthday TEXT DEFAULT "ˊ1970-1-1 00:00:00.00ˊ1970-1-1 00:00:00.00",
	phone VARCHAR(10),
	address VARCHAR(40),
	email VARCHAR(20),
	introducer CHAR(8),
	PRIMARY KEY (mId),
	UNIQUE (pId),
	FOREIGN KEY(introducer) REFERENCES Member(mId)
	ON DELETE SET NULL ON UPDATE CASCADE
);
```
`member`資料表由8個屬性組成，每個屬性有名稱及資料型別，如mId的資料型別為8字元陣列，且屬性值不可為空值(`NOT NULL`)，`mId`為資料表的**主鍵**，此外，`pId`屬性為獨一，即不可有重複值，`introducer`定義為**外部鍵**對應於member資料表的`mId`主鍵屬性。

如果不希望新增資料表時，覆蓋已有的資料表，可以使用 `IF NOT EXISTS` 修飾詞
```sql
CREATE TABLE IF NOT EXIST 資料表名稱(
.....
)
```

## 1.4 完整性限制
關聯式資料庫管理系統中完整性限制(integrty constraints)包括明確定義每筆資料的資料型態，關聯鍵限制、實體限制、外部鍵參考限制、及語意限制。在資料庫實作中必須依據資料庫設計規劃謹慎地設定資料表屬性的資料型別，以及注意下列的完整限制
* 限制屬性值不為空值(**NOT NULL**)，如 member 資料表中 `mId`、`pId`及`name`等屬性。
* 設定屬性值的預設值(**DEFAULT**)，如member 資料表中`birthday`屬性。
* 設定資料表中的主鍵(**PRIMARY KEY**)，如member 資料表中`mId`屬性。
* 設定資料表的某些屬性欄為 **UNIQUE**，即該欄的屬性值為**獨一的**，通常用於設定**次要鍵**。如member 資料表中`pId`。
* 定義外部鍵(**FOREIGN KEY**)，外來鍵必須參考到某 一個關聯的主鍵，因此，參考完整限制指序列值裡的外來鍵值，如果不是空值，則該值必須存在於其 所參考的關聯之主鍵值裡。設定外部鍵的SQL語法如下
```sql
FOREIGN KEY `屬性` REFERENCES `資料表(主鍵)`
```

> **一筆記錄被刪除或其主鍵值被修改時，其相對應的外部鍵值會受影響，在FOREIGN KEY裡的語法可以設定這些外部鍵值的處理方式

* **ON DELETE RESTRICT （為預設處理方式）**: 一筆記錄只有沒被參考時才可被刪除
* **ON DELETE SET NULL** : 一筆記錄被刪除時，所有參考它的外部鍵值全部變成空值
* **ON DELETE SET DEFAULT** : 一筆記錄被刪除時，所有參考它的外部鍵值全部變成預設值
* **ON DELETE CASCADE** : 一筆記錄被刪除時，所有參考它的記錄全部跟著被刪除
* **ON UPDATE RESTRICT （為預設處理方式）** : 一筆記錄的主鍵值只有沒被參考時才可被修改
* **ON UPDATE CASCADE** : 一筆記錄的主鍵值被修改時，所有參考它的外部鍵值全部跟著修改

## 1.5 資料表定義範例

1. 交易資料表(Transaction)
```sql
CREATE TABLE  Transactions
(
  tNo CHAR(5)    NOT NULL,
  transMId CHAR(8) NOT NULL,
  transTime DATETIME NOT NULL,
  method VARCHAR(5) NOT NULL,
  bankId VARCHAR(14),
  bankName VARCHAR(20),
  cardId VARCHAR(10),
  cardType VARCHAR(10),
  dueDate TEXT,
  PRIMARY KEY (tNo) ,
  FOREIGN KEY (transMid) REFERENCES Member(mId)
);
```
* `tNo`，`transMid`，`transTime`，`method` 屬性值不可為空值
* `tNo` 設定為主鍵
* `transMid` 設定為外部鍵，對應到會員資料表主鍵 (`member(mId)`)

2. 瀏覽紀錄資料表(Browse)
```sql
CREATE TABLE Browse
(
	mId CHAR(8)  NOT NULL DEFAULT  'a0910001',
	pNo CHAR(6)   NOT NULL,
	browseTime  DATETIME  NOT NULL,    
	PRIMARY KEY (mId, pNo, browseTime ),
	FOREIGN KEY (mId) REFERENCES Member(mId) ON DELETE SET DEFAULT  ON UPDATE CASCADE,
	FOREIGN KEY (pNo) REFERENCES Product (pNo)
);
```
* `mId`，`pNo`，`browseTime` 屬性值不可為空值
* `pNo` 設定預設值為 "a0910001"
* `mId`，`pNo`，`browseTime` 設定為主鍵
* `mId` 設定為外部鍵，對應到會員資料表主鍵 (`member(mId)`)且當一筆記錄被刪除時，所有參考它的外部鍵值全部變成預設值，及當一筆記錄的主鍵值被修改時，所有參考它的外部鍵值全部跟著修改。**在Browse中mId的資料在Member中的mId一定要存在**。
* `pNo` 設定為外部鍵，對應到商品資料表主鍵 (`product(pNo)`)

3. 商品資料表(Product)
```sql
CREATE TABLE Product
(  
  pNo CHAR(6) NOT NULL,
  pName VARCHAR(30),
  unitPrice DECIMAL(10,2),
  category VARCHAR(20),
  PRIMARY KEY (pNo ),
  CONSTRAINT UnitPrice_Check CHECK (unitPrice > 100)
);
```
* `pNo` 屬性值不可為空值
* `pNo` 設定為主鍵
* 設定一個 `CONTRAINT` 標記為 `UnitPrice_Check`，利用 `CHECK(unirPrice > 100)` 指令確保 `unitprice` 大於 100。
* > `CONSTRAINT` 用於建立一個CHECK標記(變數)，如需要修改資料表時可 `DROP CHECK [CHECK標籤]`。
## 1.6 刪除資料表 SQL 指令
```sql
DROP TABLE `tableName`
```
一資料表被刪除時，另一資料表中參考到該資料表的部分就變成沒有意義
## 1.7 修改資料表內容 SQL 指令

修改資料表名稱
```sql
ALTER TABLE `member` RENAME `members`;
```

新增一個屬性或刪除一個屬性。
```sql
-- 改變欄位名稱
ALTER TABLE `member` RENAME COLUMN `name` TO `memberName`;
-- 新增屬性
ALTER TABLE `member` ADD COLUMN `degree` VARCHAR(10);
-- 刪除屬性
ALTER TABLE `member` DROP COLUMN `degree`;
```

# 第二節 資料處理語言(Data Manipulation Language, DML)
## 2.1 新增資料 SQL 指令
已知一個資料表(product)，新增一筆紀錄存入資料表 SQL 指令範例如下
```sql
--在`product`資料表中新增一筆完整記錄
INSERT INTO `product` 
VALUES ('b00001', '資料庫理論與實務', 500, 'Book');
--在`product`資料表中新增一筆記錄只包含`pName`及`pNo`
INSERT INTO `product`(pName, pNo) VALUES ('資料庫管理與系統', 'b00001');
```

如果要一次輸入多筆資料可利用以下語法：
```sql
INSERT INTO `product` VALUES
	('b30999','資料庫理論與實務',500,'Book'),
	('d11222','任賢齊專輯三',300,'CD'),
	('b20666','OLAP 進階',500,'Book'),
	('b10234','管理資訊系統概論',600,'Book'),
	('b40555','系統分析理論與實務',550,'Book');
```

## 2.2 刪除、修改資料 SQL 指令
修改資料表中某一筆資料時，可利用以下語法；
```sql
UPDATE `product`
SET unitPrice=200, category='textbook'
WHERE pName = '資料庫理論與實務';
```
修改商品名稱為「資料庫理論與實務」的商品的單價及類別。

刪除資料表中某一筆資料時，可利用以下語法；
```sql
DELETE FROM `Product`
WHERE pName = '資料庫理論與實務';
```
將商品名稱為「資料庫理論與實務」的商品刪除

# 第三節 SQLite操作實務
## 3.1 啟動SQLite資料庫引擎
安裝完畢 SQLite 資料庫引擎，可以在 Windows 系統環境變數 `path` 中新增 `sqlite3.exe` 的執行路徑。進入作業系統命令列模式，輸入 `sqlite3.exe` 即可進入SQLite的工作環境。
![[Pasted image 20251124124319.png|500]]
如果執行`sqlite3.exe` 後沒有附加資料名稱(如example.db)，則進入SQLite環境時，並沒有設定主資料庫，此時在SQLite執行的結果儲存在一個暫存記憶體的資料庫。當我們執行完所有的工作時需要將所有結果儲存到一個資料庫(如 file.db)，這時可以使用SQLite的「點命令」`.save file.db`。如果沒有將工作結果存於一個資料庫，直接執行 `.quit` 離開資料庫引擎，將會造成所有工作結果遺失(**嗚呼哀哉!**)。

如果執行 `sqlite3.exe` 後有附加資料名稱(如example.db)，則進入SQLite環境時，將設定主資料庫為「example.db」，可以使用 `.databases`命令檢查目前作業環境的「主資料庫」(main DB)。執行 `sqlite3.exe example.db`，若 `example.db` 不存在目前工作目錄，則 SQLite 將新建一個資料庫檔案 (example.db)，反之，如果`example.db` 已存在，則SQLite將開啟 `example.db`。

進入 SQLite 後在提示符號 `sqlit>` 後可以直接輸入 SQL 指令或SQLite提供系統運作相關的點命令。

3. 讀取 csv 檔案 `.import 路徑/檔案.csv 資料表名稱`
## 3.3 將資料庫輸出
在SQLite執行的所有結果可以匯出成sql檔案，做法如下
1. 設定輸入路徑 `.output 路徑/檔案.sql`
2. 執行`.dump` 命令輸出整個資料庫(包含資料表綱要及資料)。如果只要輸出某一個資料表及資料，可以執行 `.dump 資料表名稱`，如果只輸出資料表網要(資料結構)，可以執行 `.schema`點命令。

將SQLite執行完的結果儲存成資料庫，可以使用以下點命令 `.save 資料庫名稱.db`。爾後，如果在SQLite中要開啟某一資料庫可以使用 `.read 資料庫名稱.db`點命令。
